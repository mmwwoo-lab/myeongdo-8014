# 명도재 이명우 작가 개인 홈페이지

작가 소개 → 작품 소개 → 작품해설 → 작품평론 → 문의로 이어지는 개인 포트폴리오 초기 구현본입니다.

## 포함 자료

- 홈페이지 HTML, CSS, JavaScript와 `content.json`
- 기존 작품 이미지 세 점의 웹 최적화본
- `docs/project-plan.docx`: 6쪽 업무 분담표, 일정표, 시안 방향, 해설 및 평론 양식, 검수 기준
- `docs/author-input.md`: 작가 확인 항목
- `docs/research-notes.md`: 공개 자료 조사 기록과 이미지 출처

## 실행 방법

첫 화면의 **홈페이지 만들기**를 누르면 `admin/#create` 제작기가 열립니다. **명도재 작가 자료로 홈페이지 만들기**로 소개와 작품 세 점을 불러온 뒤 자유롭게 수정할 수 있습니다. **전시관 바로 보기**는 실제 HTML을 생성해 보여 주며, **전시 프로젝트 저장**은 브라우저에 저장합니다. 권한 확인 체크 후 **전시 홈페이지 완성 · 다운로드**로 독립 HTML 파일을 만듭니다.

파일 생성은 토큰 없이 작동합니다. 제작기에서 GitHub에 직접 새 전시를 공개하는 기능은 사용자가 해당 저장소의 쓰기 토큰을 입력해야 하며, 이 토큰은 저장하지 않습니다. 파일 다운로드와 온라인 공개는 별도입니다.

## 6단계 협업

제작 화면에 총괄 지시 → 작품 자료 조사 → 전시 기획·평론 → 음악·영상 제작 → 전시 웹 제작 → 검수·공개를 제공합니다. 각 단계에 담당자, 상태, 자료와 사용 허락 근거, 작업 메모를 기록합니다. 프로젝트 JSON에 이 기록이 포함되어 다음 담당자가 가져와 이어서 작업할 수 있으며, 협업 보고서도 내려받습니다. 실시간 공동 편집이나 담당자 인증 기능은 아닙니다. 승인 완료 표시는 입력자가 남긴 승인 기록입니다.

GitHub 저장소에서는 `index.html`이 있는 폴더에서 `python3 -m http.server 8000`을 실행한 뒤 브라우저로 `http://localhost:8000`을 엽니다.
Sites 원본 작업 폴더에서는 정적 파일이 `dist/`에 있습니다. 서버를 통해 열어야 `content.json`을 불러올 수 있습니다.

## 내용 수정

작가소개와 작품의 제목·정보·해설·평론은 `content.json`에서 수정합니다. 화면에 표시한 `[검색 필요]`, `[작가 입력 필요]`와 초안 표기를 실제 확인 결과에 맞게 갱신합니다. 작업 연도와 실물 재료·크기는 임의로 채우지 않습니다.

문의 폼은 입력 내용을 복사하는 기능입니다. 자동 이메일 발송과 서버 저장은 연결하지 않았습니다. 이메일이 확정되면 별도 발송 기능을 추가할 수 있습니다.

## 검수 현황

2026년 10월 26일 기준 문서 6쪽의 렌더링을 확인했고, 웹 화면과 작품 필터·상세 보기 동작을 점검했습니다. 프로필 사진, 정식 작품명, 작품의 연도·실물 재료·크기, 최종 철학, 이메일은 작가 확인이 필요합니다. 모바일은 반응형 규칙을 구현했으며 실제 휴대전화 확인은 추가로 진행합니다.

## 공개와 권리

작품해설과 비평은 이미지 관찰을 바탕으로 작성한 AI 초안입니다. 외부 평론가의 기고나 작가 본인의 진술로 표시하지 않습니다. 작품 이미지의 재사용·출력·배포 범위는 작가에게 확인해 주세요. 이 저장소의 업로드는 GitHub Pages 호스팅 설정을 자동으로 활성화하지 않습니다.

## 2026-10-26 작업실 및 협업 파일 구성

이 저장소는 **홈페이지 첫 화면(`index.html`)**과 **작가 개인 홈페이지 제작기(`admin/index.html`)**가 함께 제공됩니다.

| 파일 | 역할 |
|---|---|
| `index.html` | 명도재 이명우 개인 홈페이지 및 6단계 협업 안내 |
| `style.css`, `app.js`, `content.json` | 공개 개인 홈페이지 디자인·작품 데이터·인터랙션 |
| `assets/*.webp` | 작가 작품 예시 이미지 3점 |
| `admin/index.html` | 개인 전시 홈페이지 제작기, 작품 등록, 작가 사진 및 이름, 음악·영상 |
| `admin/app.js`, `admin/style.css` | 등록·저장·미리보기·다운로드 및 디자인 |
| `admin/collaboration.js`, `admin/collaboration.css` | DIRECTOR부터 REVIEW까지 협업 상태·근거·체크리스트·최종 승인 기록 |
| `admin/starter.js` | 작가 데이터와 이미지로 시작하기 |
| `docs/collaboration-workflow.md` | 단계별 협업·인수인계·승인 기록 지침 |
| `tests/check-site.cjs` | 필수 파일 및 협업 기능의 정적 자동 검증 |

### 협업 시작

1. 홈페이지의 **6단계 협업**에서 흐름을 확인하거나 **홈페이지 만들기**로 제작기를 엽니다.
2. 작가·전시 기본정보를 입력하고 사이드바의 **6단계 협업 작업실**에서 단계별 담당자와 결과를 기록합니다.
3. 다른 담당자와 이어서 작업할 때는 전시 프로젝트 JSON 백업을 전달하거나, 각 단계에서 **GitHub 업무 요청서**를 열어 이슈로 공유합니다.
4. REVIEW 단계에서 공개 권리·링크·재생·모바일·접근성을 확인하고 DIRECTOR에서 최종 공개 승인 기록을 남깁니다.

**제약:** 상태 기록은 입력자가 작성한 자기 신고 방식입니다. 사용자 인증, 실시간 공동 편집, 신뢰할 수 있는 전자 승인·전자서명은 구현되어 있지 않습니다. GitHub 이슈는 실제 공동 작업에 사용할 수 있지만, 이슈를 만들려면 GitHub에서 직접 로그인·제출해야 합니다.

### GitHub Pages 공개 설정

파일은 `main` 브랜치의 루트에 저장됩니다. 저장소의 **Settings → Pages → Build and deployment → Source**에서 **`GitHub Actions`**를 선택해 저장하세요. `.github/workflows/deploy-pages.yml`이 `main` 브랜치의 정적 홈페이지 전체를 배포합니다. 처음에는 저장소 소유자의 Pages 활성화 설정이 필요합니다. 배포가 즉시 시작되지 않으면 Actions 탭에서 `Deploy Myeongdo 8014 Website` 작업을 다시 실행하세요. 설정이 완료되면 일반적으로 다음 주소를 사용할 수 있습니다.

- 공개 홈페이지: `https://mmwwoo-lab.github.io/myeongdo-8014/`
- 홈페이지 제작: `https://mmwwoo-lab.github.io/myeongdo-8014/admin/#create`

**현재 점검 결과 GitHub Pages가 아직 활성화되지 않아 `Configure GitHub Pages` 단계가 실패합니다.** 코드 자동 검증 및 브라우저 점검과 사이트 공개 여부는 서로 별개입니다. 파일 업로드만으로 호스팅이 활성화되지는 않습니다.
